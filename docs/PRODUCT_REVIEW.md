# ESP32-P4 SDR Modem 产品与商业化评审

评审日期：2026-09-09。依据 embedded-dev 技能、当前源码与实机记录，以及当日查阅的官方产品资料。目标客户已由用户明确为中国大陆的无线电爱好者／业余无线电用户；交付形态暂按个人或小团队的小批量产品考虑。

**结论：值得继续做限定范围的产品验证，有小众商业化潜力；当前适合工程原型，尚不具备成熟整机交付证据。固件的职责划分总体合理，最需要调整的是产品范围和完整使用流程。** 本次没有客户访谈、订单、整机供应商报价或新的射频实测，因此不能据此断言销量、盈利或量产就绪。

**1. 谁可能购买，为什么购买**

“无线电爱好者”仍包含不同任务。建议首先验证其中已有 SSB 电台、希望在便携或桌面场景脱离电脑完成数字通联的人。买方通常也是使用者；其真正需要的是接线明确、几分钟内进入通信、能编辑内容、收发状态可靠、能与已有软件／电台配合。

候选主卖点是：**面向指定电台的中文独立数字通信终端，附匹配线材、设置向导和经过验证的协议。** “无需电脑”的价值必须在用户完整操作中成立，不能依靠开发者串口下命令才能发送自定义内容。

另一个人群是主要看频谱、收飞机、研究遥控信号的接收爱好者。这个方向可以验证为接收版或实验功能包，但它与短波数字通联的购买理由不同。现在没有证据证明同一买方愿意为两套工作流程共同加价。

首批接触渠道建议是自己能直接接触的本地无线电俱乐部、熟悉的业余电台用户及已有数字模式交流圈。让对方展示最近一次使用流程，比泛泛询问“想不想要多功能 SDR”更有用。目前这些只是候选渠道，尚未开展联系或获得付费证据。

这能证明存在相关产品类别和替代品，不能证明本项目已存在需求。若用户主要要求 FT8、Winlink 或 RADE，当前功能组合就需要重新评估；库文件存在也不代表已实现这些模式。

**3. 当前设计的合理部分与关键缺口**

| 项目 | 当前事实与证据 | 判断／交付前要补的工作 |
|---|---|---|
| 主控和板级平台 | ESP32-P4、32 MiB PSRAM、USB HS、1024×600 MIPI 屏、ES8311；无线由 C6 协处理器承担。见 [集成记录](C:/projects/esp32-sdr-modem/docs/SDR_PORT.md:99) | 与现有显示／USB／DSP 组合匹配。现阶段换 MCU 会增加移植和回归工作，应保留 P4 验证用户价值；将来若只做音频附件，可再缩小硬件 |
| 固件职责 | USB 生命周期和调谐由 rtlsdr 管理，服务层负责队列／DSP；IQ、PCM 带配置代次；同锁处理 SDR 与 TX 的互锁。见 [服务层](C:/projects/esp32-sdr-modem/main/sdr_service.c:380) | 对异步流处理的方向合理，值得保留。单一 DAC 写入者和有界队列降低冲突风险，但真实 USB 负载下的效果仍需实测 |
| 输入与收发状态 | Tx 请求会关闭 SDR 输入，录制中拒绝进入 Tx；RTL-SDR 只接收 | 逻辑边界正确。屏幕 Tx 是调制音频输出状态，不能让用户误解为接收棒可以射频发射；外部电台是否已被正确键控要另行确认 |
| 电台连接 | 当前走 BSP 麦克风／扬声器音频。未在 main、板级配置及当前集成文档中看到已实现并验收的外部硬件 PTT、CAT 和电台音频接口方案。见 [音频入口](C:/projects/esp32-sdr-modem/main/audio_input.c:75) | 这是做业余电台附件的核心缺口：输入输出电平、衰减／隔离、PTT 电气兼容、线序和适配电台都应明确；CAT 仅在目标电台工作流程确实需要时加入 |
| 独立文字通信 | 自定义文字可从串口 `TX <text>` 设置；默认内容仍是 HPM6750 板间测试文字。LCD 文本区是显示标签，现有键盘用于接收频率数字输入。见 [命令入口](C:/projects/esp32-sdr-modem/main/ui.c:301) | 发送路径已有基础，但还没有完成面向用户的独立文字输入、呼号配置、常用短语和日志保存流程。界面美化无法代替这些步骤 |
| 数字语音互通 | 当前为项目自定义 Codec2/PSK 空口，未实现完整 FreeDV 700D/700E。见 [当前能力](C:/projects/esp32-sdr-modem/README.md:20) | 需要另一端运行匹配协议。适合实验或明确需要成对设备的客户；不能作为通用 FreeDV 终端销售 |
| 自制接收棒与 HF | 当前 A.2 是 RTL2832U + R820T2 调谐器链路，未配置 HF 上变频或 HF 直接采样输入 | 它不能仅靠页面选项就覆盖 7／14 MHz 等短波用途。音频附件路线可直接使用用户电台的接收音频；独立 HF 接收路线则必须补实际前端 |
| ADS-B／Sub-GHz | 飞机列表和离线海岸线地图已实现；最多 24 个目标。OOK 提供原始脉宽，未完成具体传感器协议、LoRa／FSK 解码 | 已经超过空白页面，但需要真实接收验收。不能把海岸线图包装为完整地图服务，也不能把原始 OOK 称为“解析所有 433 MHz 设备” |
| IQ 记录 | 上限 512 KiB CU8，Record 模式为 288 kS/s；当前实机 SPIFFS 挂载失败，Flash 保存不可用。见 [常量](C:/projects/esp32-sdr-modem/main/sdr_types.h:6)、[保存状态](C:/projects/esp32-sdr-modem/docs/SDR_PORT.md:123) | `524288 ÷ (288000 × 2) ≈ 0.91 秒`，适合短片段抓取，不能作为长时间录波卖点；是否扩展存储应由使用任务决定 |
| UI 管理 | 两个工作区已有共用主题、页面管理、频段目录及地图数据来源 | 保留共享机制；下一步优先统一中文术语、连接／接收／发射状态、错误恢复及操作反馈，把帧计数和十六进制诊断移到详情 |

资源判断要看内部 SRAM、DMA 缓冲和任务栈，而不是只看还剩多少 PSRAM。最新无接收棒观察中，内部空闲约 76.9 kB、最大连续块 31.7 kB；尚不能用这些数值证明接入 USB 后仍有足够裕量。

软件互锁也不等于射频硬件隔离。如果把接收棒与发射电台组合，必须另行设计并测量发射时的接收前端保护；特别是共用天线时，不能直接从软件停流推断电气安全。

**4. 自制 PCB 是否适合商业交付**

本次以已经更新的 **A.2** 为准，依据 [设计说明](C:/projects/kicad-projects/generated/rtlsdr_dongle/DESIGN_NOTES.md) 和 [采购核查](C:/projects/kicad-projects/generated/rtlsdr_dongle/DOMESTIC_SOURCING.md)，未重新运行 KiCad ERC／DRC，也未进行电路修改。

A.2 已明确国内 TCXO、SMA 和大部分常用料，时钟的温度稳定度与初始误差也做了区分，这是进展。但 RTL2832U／R820T2 的可靠批次供货尚未确认；参考 75 Ω 匹配网络接到 50 Ω SMA 的实际接收性能、USB 信号完整性、LDO 温升、端口防护仍待测量。这些问题使它目前仍是待验证的接收模块，不能因为 BOM、Gerber 或 DRC 就判断可批量交付。

建议把首轮需求验证与自制 RF 板验证分开：先用已确认型号的商用接收棒或电台音频接口完成用户任务，再决定自制板是否有明确成本、结构或性能收益。不要默认任意新款接收棒兼容：官方新 V4L 使用 R828S，并明确需要更新驱动；当前项目 V4 分支针对 R828D，V4L 兼容性没有验收。[官方产品说明](https://www.rtl-sdr.com/buy-rtl-sdr-dvb-t-dongles/)

无线功能可以成为装配或固件选项，但当前入口仍无条件启动 Wi-Fi Web 服务。若去掉 C6／Wi-Fi，应同时补齐本地设置、导出和升级途径；这不是本次已经完成的改动。现有大屏适合桌面或可搬运终端，若承诺口袋便携，需要先取得用户对尺寸、供电和续航的实际要求。

**5. 首版范围建议**

下表是商业优先级建议，不代表删除现有 ADS-B、Sub-GHz 等用户要求的功能。可以保留在实验入口，共用底层代码，但只对经过验收的能力作销售承诺。

| 范围决定 | 内容 | 用户价值与验证依据 | 主要开发／长期成本；恢复条件 |
|---|---|---|---|
| 首版必须 | 指定 1～2 款电台的音频与 PTT 连接、配套线材、电平向导 | 能接上电台并重复完成通联；当前未完成验收 | 电气适配、线材品控、现场支持；先限制兼容矩阵 |
| 首版必须 | 少量目标客户实际使用的标准文字模式、双向互通 | 与已有对端通信；当前只有主机算法和有限板级证据 | 频偏、音量、失锁及对端兼容测试；具体模式由目标用户案例决定 |
| 首版必须 | 呼号／文字输入、常用短语、保存结果、断线恢复、版本识别及本地升级方式 | 完成从开机到通联及复查的整个流程 | UI、持久化和维护说明；不强制加入云、OTA 或电池 |
| 待验证加入 | 标准 FreeDV 某个明确模式 | 仅在客户确有数字语音对端时有价值 | 协议移植、实时预算、互通维护；不能只复用 Codec2 就承诺完成 |
| 后续选配 | RTL-SDR 瀑布图、ADS-B／离线飞机图、Sub-GHz 原始捕获 | 服务接收／学习任务，付费贡献未知 | 天线、前端、2 MS/s 负载、解码和多场景支持；观察到重复使用需求后提升优先级 |
| 实验功能保留 | 自定义 Codec2 空口、图像、长模式菜单 | 研究与板间实验已有积累 | 限定实验状态；明确成对客户需求或完成标准互通后再成为主卖点 |

推荐完整首次使用路径：拿到已配线的设备 → 选择已支持的电台配置 → 看电平／削顶提示调整 → 设置呼号并编辑文字 → 接收对方内容 → 发送并确认电台回到接收 → 保存日志。任一步仍需要开发者命令行操作，就要把它计入试用服务，而不是宣称普通用户可独立使用。

**6. 可靠性证据到哪里为止**

已有证据值得保留：生产 C／LVGL 主机检查覆盖了 DSP、PSK、ADS-B CRC／CPR、分片、地图和页面；真实板上修复了启动时的栈和内存问题。较早修复版无接收棒运行约 10 分钟、完成 11 轮不同内容 Tx/Rx；最新 UI 固件另有 180.172 秒观察及两轮 Audio Tx/Rx 共 61.140 秒，均没有记录到意外重启。版本及原始日志路径见 [实机记录](C:/projects/esp32-sdr-modem/docs/SDR_PORT.md:99)。

这些记录来自不同阶段固件，不能相加当作当前版本的连续稳定性时长。用户明确暂时没有接收棒，因此真实 RF、USB 连续收流、实际飞机、外部电台通联及批量硬件一致性仍未验收。SPIFFS 挂载失败也尚未修复。正确成熟度描述是“可运行并有部分验证的工程原型”。

下一轮工程验收应绑定最终首版承诺：

- 数字通信附件：使用目标电台与独立对端实现双向文字互通，记录首次成功时间、频偏／音量范围、错误率及掉线后的恢复；先完成可控音频链路，再做合规实际通联。
- 若首版包含 SDR：对指定接收棒测 USB 枚举、拔插恢复、调谐和真实 RF。若承诺 ADS-B，再加入 2 MS/s 连续流及接收效果对照，不能只跑低采样率待机。
- 建议将 24 小时承诺负载、100 次模式切换、20 次 USB 拔插作为下一轮原型目标值：无意外重启／死锁，断开后能恢复，记录堆最低水位、连续最大块、丢样和热状态。次数是测试计划，尚未执行，也不是认证或寿命结论。
- 小批前形成最短装配、烧录、音频／RF 功能检查和序列号记录；执行与实际功能有关的掉电／升级失败恢复。测量显示屏、供电和无线活动对接收性能的影响。

**7. 收入判断与成本边界**

目前没有整机 BOM 报价、结构和线材报价、测试工时或返修率，不建议直接给出“售价多少、利润多少”的确定结论。自制 dongle 的元件采购表也不能代表整机成本。

应统一含税／未税和退款口径，计算：

`单台贡献 = 同口径净收入 − 硬件／装配／线材／包装 − 测试与交付工时 − 渠道／运输 − 预期返工和售后变动成本`

固定研发、工装单列，避免又计入每台又计入固定投入。下面仅演示敏感性，**不是售价建议、真实成本估算或销量预测**：

| 假设单台净收入 | 假设完整变动成本 | 单台贡献 | 若另有固定投入 30,000 元，覆盖所需交付量 |
|---|---|---|---|
| 900 元 | 400 元 | 500 元 | 60 台 |
| 900 元 | 600 元 | 300 元 | 100 台 |
| 900 元 | 800 元 | 100 元 | 300 台 |

这说明售后和适配工时可能决定项目是否赚钱。若每个客户都需要开发者单独接线、改固件，必须作为有范围的付费服务定价；不能把这些工作无限免费附送，再用裸 BOM 差价计算利润。正式定价应等待同一交付范围的真实报价与试用反馈。

许可同样影响交付：现有 RTL-SDR 移植含 GPL-2.0-or-later，Codec2 保留 LGPL-2.1。见 [项目归属说明](C:/projects/esp32-sdr-modem/third_party/rtl-sdr-blog/README.md)。GPL 允许商业销售，但分发组合固件时要按适用许可履行源码等义务，不能只提供上游链接就默认足够；应整理最终固件的许可清单、对应修改源码与构建材料。[GNU 商业销售说明](https://www.gnu.org/philosophy/selling.en.html) 产品优势应放在完成度、适配、交付和支持上。

大陆接收频段预设不能暗示“433 MHz 任意发射无需许可”；微功率设备的豁免附有目录、用途和技术条件。[工信部 2019 年第 52 号公告](https://www.miit.gov.cn/zwgk/zcwj/wjfb/gg/art/2020/art_4f2c890530cc4837b2113cf977e249c4.html) 最终应按实际交付是否含无线发射、设备类别和销售范围确认适用要求；不能把 RX-only 接收棒、音频附件和整套无线电台视为同一类别。

**8. 最有价值的下一步**

建议先做一次有上限的“独立数字通联”验证，而不是继续增加模式或同时重做主控、射频和外壳。计划可控制在两周、最多 40 工时和 2,000 元新增验证支出内；这些是用于约束试验的建议上限，不是完成整机研发的报价，也没有授权或发生支出。优先借用电台／接收棒，若资源不足则缩小验证范围。

先从可直接接触的用户中选 4～6 位近期实际用过 SSB 数字模式的人：

1. 展示最近一次通联的现有设备、步骤和遇到的问题；记录“不买新设备继续现状”是否已经足够好。
2. 用指定电台和一个明确模式交付一次完整任务。把开发者帮助的次数和分钟数计入记录，再观察用户第二次是否能自行完成。
3. 在硬件报价与服务范围明确后给出具体试用方案，核实是否愿意按覆盖变动成本和支持成本的价格进入付费试用；口头称赞、点赞不算订单。
